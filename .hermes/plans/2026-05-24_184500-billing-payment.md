## 2. Database Migration (`server/migrate.js`)

### 2.1 Tabel Baru

```sql
-- Subscriptions: menghubungkan client dengan paket + billing cycle
CREATE TABLE IF NOT EXISTS subscriptions (
  id INT AUTO_INCREMENT PRIMARY KEY,
  client_id INT NOT NULL,
  package_id INT NOT NULL,
  status VARCHAR(20) DEFAULT 'active'
    CHECK(status IN ('active', 'suspended', 'terminated', 'cancelled')),
  billing_cycle VARCHAR(20) DEFAULT 'monthly'
    CHECK(billing_cycle IN ('monthly', 'quarterly', 'semi_annual', 'yearly')),
  activation_date DATE,
  next_billing_date DATE,
  last_billing_date DATE,
  suspended_at TIMESTAMP NULL,
  termination_reason TEXT,
  auto_renew TINYINT(1) DEFAULT 1,
  notes TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (client_id) REFERENCES clients(id) ON DELETE CASCADE,
  FOREIGN KEY (package_id) REFERENCES service_packages(id) ON DELETE RESTRICT
) ENGINE=InnoDB;

-- Invoices: semua transaksi tagihan
CREATE TABLE IF NOT EXISTS invoices (
  id INT AUTO_INCREMENT PRIMARY KEY,
  invoice_number VARCHAR(50) UNIQUE NOT NULL,
  subscription_id INT,
  client_id INT NOT NULL,
  package_id INT,
  amount DECIMAL(12,2) NOT NULL DEFAULT 0,
  tax_amount DECIMAL(12,2) DEFAULT 0,
  total_amount DECIMAL(12,2) NOT NULL DEFAULT 0,
  status VARCHAR(20) DEFAULT 'unpaid'
    CHECK(status IN ('draft', 'unpaid', 'paid', 'overdue', 'cancelled', 'refunded')),
  issue_date DATE NOT NULL,
  due_date DATE NOT NULL,
  paid_at TIMESTAMP NULL,
  paid_amount DECIMAL(12,2) DEFAULT 0,
  payment_method VARCHAR(50),
  notes TEXT,
  pdf_path VARCHAR(255),
  billing_period_start DATE,
  billing_period_end DATE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (subscription_id) REFERENCES subscriptions(id) ON DELETE SET NULL,
  FOREIGN KEY (client_id) REFERENCES clients(id) ON DELETE CASCADE,
  FOREIGN KEY (package_id) REFERENCES service_packages(id) ON DELETE SET NULL
) ENGINE=InnoDB;
CREATE INDEX idx_invoices_status ON invoices (status);
CREATE INDEX idx_invoices_client ON invoices (client_id);
CREATE INDEX idx_invoices_due ON invoices (due_date);

-- Payments: riwayat pembayaran
CREATE TABLE IF NOT EXISTS payments (
  id INT AUTO_INCREMENT PRIMARY KEY,
  invoice_id INT NOT NULL,
  client_id INT NOT NULL,
  amount DECIMAL(12,2) NOT NULL,
  payment_method VARCHAR(50) NOT NULL,
    -- midtrans_va, midtrans_qris, midtrans_ewallet, midtrans_cc, manual_transfer, cash
  payment_channel VARCHAR(100),
  transaction_id VARCHAR(100) UNIQUE,
    -- Midtrans order_id / transaction_id
  status VARCHAR(20) DEFAULT 'pending'
    CHECK(status IN ('pending', 'success', 'failed', 'expired', 'refunded')),
  paid_at TIMESTAMP NULL,
  payment_details JSON,
    -- Full Midtrans response
  notes TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (invoice_id) REFERENCES invoices(id) ON DELETE CASCADE,
  FOREIGN KEY (client_id) REFERENCES clients(id) ON DELETE CASCADE
) ENGINE=InnoDB;
CREATE INDEX idx_payments_invoice ON payments (invoice_id);
CREATE INDEX idx_payments_transaction ON payments (transaction_id);

-- Payment gateway settings (bisa via form admin)
CREATE TABLE IF NOT EXISTS payment_settings (
  id INT AUTO_INCREMENT PRIMARY KEY,
  gateway VARCHAR(50) NOT NULL UNIQUE,
    -- 'midtrans', 'xendit'
  is_active TINYINT(1) DEFAULT 0,
  merchant_id VARCHAR(100),
  client_key VARCHAR(255),
  server_key VARCHAR(500),  -- encrypted
  environment VARCHAR(10) DEFAULT 'sandbox'
    CHECK(environment IN ('sandbox', 'production')),
  sandbox_url VARCHAR(255),
  production_url VARCHAR(255),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- Invoice items: baris detail invoice
CREATE TABLE IF NOT EXISTS invoice_items (
  id INT AUTO_INCREMENT PRIMARY KEY,
  invoice_id INT NOT NULL,
  description VARCHAR(255) NOT NULL,
  quantity INT DEFAULT 1,
  unit_price DECIMAL(12,2) NOT NULL,
  subtotal DECIMAL(12,2) NOT NULL,
  type VARCHAR(20) DEFAULT 'subscription'
    CHECK(type IN ('subscription', 'setup', 'topup', 'penalty', 'discount', 'other')),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (invoice_id) REFERENCES invoices(id) ON DELETE CASCADE
) ENGINE=InnoDB;
```

## 3. Backend — Routes & Services

### 3.1 Invoice Number Generator

`server/services/invoice-number.js`
- Format: `INV/YYYYMM/XXXX` (auto-increment per bulan, reset tiap tahun)
- Atau: `INV/MAZNET/YYYYMM/XXXX`

### 3.2 Invoice Engine

`server/services/invoice-engine.js`
- `generateInvoice(clientId, subscriptionId, periodStart, periodEnd)` — create invoice + invoice_items
- `generatePDF(invoiceId)` — generate PDF dengan pdfmake/pdfkit
- `getInvoiceNumber()` — ambil nomor invoice berikutnya

**Scheduled jobs (node-cron):**
- `0 2 1 * *` (tgl 1 tiap bulan 02:00) — generate semua invoice untuk subscription active dengan billing_cycle monthly
- `0 3 * * *` (setiap hari 03:00) — overdue detection → update status invoice jadi 'overdue'
- `0 4 * * *` (setiap hari 04:00) — auto-suspend subscription jika overdue > 14 hari (sesuai payment_terms client)
- `0 5 * * *` (setiap hari 05:00) — auto-activate subscription yg baru bayar

### 3.3 Midtrans Payment Gateway

`server/services/payment/midtrans.js`
- `createTransaction(invoiceId, paymentMethod)` — create Midtrans transaction
  - Payment methods: `bank_transfer` (BCA/BNI/Mandarin), `gopay`, `qris`, `cstore` (Indomaret/Alfamart)
  - Generate Snap URL / token
- `handleNotification(notificationBody)` — webhook handler untuk Midtrans payment notification
  - Update invoice status → `paid`
  - Create payment record
  - Update subscription `next_billing_date`
- `getTransactionStatus(orderId)` — cek status transaksi

**Webhook endpoint:** `POST /api/payments/midtrans-webhook` (tidak pakai auth — Midtrans signature)

### 4.4 Midtrans Snap Integration

Implementasi **server-side Snap** (recommended — lebih secure daripada client-side):

1. Backend: `POST /api/payments/midtrans-charge` → panggil Midtrans Snap API → return `redirect_url`
2. Frontend: redirect ke `redirect_url` atau tampilkan Snap popup via Midtrans JS SDK
3. Webhook: Midtrans kirim POST ke `https://domain/api/payments/midtrans-webhook` → update status

**Snap Popup Frontend:**
```html
<script src="https://app.sandbox.midtrans.com/snap/snap.js" data-client-key="..."></script>
```
Di React: panggil `window.snap.pay(token, callback)` setelah backend return Snap token.

## 8. Testing & Verification

### Manual Test Cases
1. **Invoice Generation**: Create subscription → trigger monthly → verify invoice + items created
2. **Midtrans Payment**: Pay invoice via Midtrans Snap → verify webhook → status jadi `paid`
3. **Overdue Detection**: Set due_date kemarin → run cron → status jadi `overdue`
4. **Auto-Suspend**: Overdue > 14 hari → subscription jadi `suspended`
5. **Manual Payment**: Input manual transfer → verify → subscription status tetap active
6. **PDF Download**: Klik download → PDF ter-generate + isi benar
7. **Dashboard Stats**: Revenue/MRR/outstanding muncul di dashboard

### Edge Cases
- Generate invoice untuk subscription yang suspended — skip
- Double payment notification dari Midtrans (idempotent via transaction_id)
- Invoice cancellation setelah partial payment — refund logic? (handled manual dulu)
- Client tanpa subscription — tidak generate invoice
- FUP implementation — handle di phase terpisah (integrasi Mikrotik)

## 9. Risiko & Mitigasi

| Risiko | Mitigasi |
|--------|----------|
| Midtrans sandbox vs production key kebalik | Field environment explicit (sandbox/production) dengan visual indicator |
| Double invoice generation | Cek unique constraint (subscription_id + period) |
| PDF invoice formatting error | Simpan raw HTML juga sebagai fallback |
| Webhook Midtrans missed (server down) | Retry mechanism + manual verify button di admin |
| Encrypted server_key bermasalah | Pake `encrypt()`/`decrypt()` dari utils/encryption.js (existing pattern) |
