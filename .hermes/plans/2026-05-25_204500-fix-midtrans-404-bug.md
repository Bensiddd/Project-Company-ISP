# Plan: Fix Midtrans 404 "Transaction doesn't exist" Bug

## Goal
Diagnosa dan fix error:
```
Midtrans error: Midtrans API is returning API error. HTTP status code: 404.
API response: {"status_code":"404","status_message":"Transaction doesn't exist.","id":"..."}
```
yang muncul saat user switch mode Sandbox ↔ Production di Payment Settings.

---

## 1. Root Cause Analysis

### Error Origin
Error **`"Transaction doesn't exist"` (HTTP 404)** berasal dari **Midtrans Core API** saat dipanggil method `transaction.status(orderId)` — memeriksa status transaksi yang tidak ada.

Midtrans SDK (`midtrans-client`) melempar error dengan format:
```
"Midtrans API is returning API error. HTTP status code: {code}. API response: {body}"
```

### 3 kemungkinan sumber error di kode:

| No | Sumber | Method | Penyebab |
|----|--------|--------|----------|
| **A** | `POST /payment-settings/test` (`payment-settings.js:42-88`) | `core.transaction.status(dummyId)` | Dipanggil saat "Test Connection". **Seharusnya** catch 404 → return success. TAPI jika `error.httpStatusCode` undefined, fallthrough ke `Connection failed: ${error.message}` |
| **B** | `POST /payments/midtrans-charge` (`payments.js:78-155`) | `snap.createTransaction(params)` | Dipanggil saat user klik "Midtrans Charge" di Payments page. Jika server key mismatch environment, Midtrans return 404. Backend return 500 → frontend silent console.error |
| **C** | `POST /payments/webhook` (`payments.js:158-221`) | `core.transaction.notification(payload)` | Jika ada notifikasi webhook dengan order_id palsu. Tapi ini server-side, user tidak lihat |

### Paling mungkin: **Source B/C dengan key mismatch**

Flow tipikal:
1. User setting Sandbox → simpan **`SB-Mid-server-xxxx`** key
2. User buat payment via Midtrans (Sandbox) → tersimpan `transaction_id = INV-1-12345`
3. User switch ke **Production** di Payment Settings
4. User buka Payments page → klik "Midtrans Charge" untuk invoice yang sama
5. Backend panggil `snap.createTransaction()` dengan `isProduction: true` (dari DB) tapi **server_key masih sandbox** → Midtrans Production API reject → error

### Root Cause: **Missing validation bahwa server_key cocok dengan environment**

Tidak ada validasi bahwa `SB-Mid-server-*` key hanya untuk sandbox dan `Mid-server-*` key hanya untuk production. User bisa save sandbox key + production mode (atau sebaliknya).

## 2. Step-by-Step Fix

### Phase 1: Diagnostik (konfirmasi sumber)

- [x] **Cek test endpoint**: Apakah 404 benar2 di-handle sebagai success?
  - File: `server/routes/payment-settings.js:60-68`
  - ✓ Sudah benar: `if (httpStatus === 404) return res.json({ success: true, ... })`

- [x] **Cek frontend error display**: Apakah error muncul dari Toast atau console?
  - `Payments.jsx:115` → silent `console.error(e)` — user tidak lihat
  - `PaymentSettings.jsx:101-106` → `handleTest()` → show testResult

- [x] **Cek key prefix validation**: Apakah ada guard `SB-Mid-server-` vs `Mid-server-`?
  - `payment-settings.js:72-77` → Ada di test endpoint! Tapi **hanya** untuk kasus 401, bukan 404.

### Phase 2: Fix Server Key Validation

**File: `server/routes/payment-settings.js`**

**Fix A** — Tambah validasi server_key prefix di save endpoint:
```javascript
// Sebelum save, validasi key prefix match environment
if (server_key) {
  const isSandboxKey = server_key.startsWith('SB-Mid-server-');
  const isProductionKey = server_key.startsWith('Mid-server-');
  if (!isSandboxKey && !isProductionKey) {
    return res.status(400).json({ message: 'Invalid server key format' });
  }
  if (is_sandbox && !isSandboxKey) {
    return res.status(400).json({
      message: 'Sandbox key harus dimulai dengan SB-Mid-server- (kamu pakai Production key di mode Sandbox)'
    });
  }
  if (!is_sandbox && isSandboxKey) {
    return res.status(400).json({
      message: 'Production key harus dimulai dengan Mid-server- (kamu pakai Sandbox key di mode Production)'
    });
  }
}
```

**Fix B** — Tambah `return` sebelum `res.json()` baris 86 untuk prevent double-response:
```javascript
return res.json({ success: false, message: `Connection failed: ${error.message}` });
```

### Phase 3: Fix Midtrans Charge Error Handling

**File: `server/routes/payments.js`**

**Fix C** — Perbaiki `/midtrans-charge` error handling agar lebih informatif:
```javascript
} catch (error) {
  console.error('Midtrans charge error:', error);
  const httpStatus = error.httpStatusCode || error.statusCode;
  const isSandboxKey = settings.server_key?.startsWith('SB-Mid-server-');
  const envMismatch = (settings.is_sandbox && !isSandboxKey) || (!settings.is_sandbox && isSandboxKey);

  let message = 'Failed to create payment';
  if (envMismatch) {
    message = 'Server key tidak cocok dengan environment. Cek Payment Settings.';
  } else if (httpStatus === 401) {
    message = 'Midtrans authentication failed — server key invalid.';
  } else if (httpStatus === 404) {
    message = 'Midtrans merchant tidak ditemukan. Cek Merchant ID & server key.';
  }

  res.status(500).json({ message, error: error.message });
}
```

### Phase 4: Fix Frontend UX

**File: `src/pages/admin/PaymentSettings.jsx`**

**Fix D** — Tambah environment status indicator di UI:
```jsx
// Di sebelah tombol Save, tampilkan peringatan jika key mismatch
{form.server_key && (
  <div style={{ fontSize: 12, marginTop: 8, color: '...' }}>
    {form.is_sandbox && !form.server_key.startsWith('SB-Mid-server-')
      ? '⚠️ Sandbox key harus SB-Mid-server-...'
      : !form.is_sandbox && form.server_key.startsWith('SB-Mid-server-')
      ? '⚠️ Production key tidak boleh SB-Mid-server-...'
      : '✅ Key format sesuai environment'}
  </div>
)}
```

**Fix E** — Di Payments page, tampilkan error toast saat midtrans charge gagal:
```jsx
// Payments.jsx handleMidtransCharge - ubah dari silent catch
catch (e) {
  console.error(e);
  const msg = e.response?.data?.message || e.message || 'Midtrans charge failed';
  showToast({ type: 'error', title: 'Payment Failed', subtitle: msg });
}
```

### Phase 5: Prevent stale midtrans transaction retries

**File: `src/pages/admin/Payments.jsx`**

Saat user memiliki payment record dari environment lama (sandbox), dan sekarang sudah pindah ke production, tombol "Midtrans Charge" akan gagal karena order_id prefix berbeda.

**Fix F** — Jangan tampilkan tombol "Midtrans Charge" jika payment method midtrans tapi sudah expired/berbeda session:
```jsx
// Ubah kondisi button retry
{p.payment_method === 'midtrans' && p.invoice_id && p.status === 'pending' && (
  <button ...>Retry Midtrans</button>
)}
```
Existing sudah benar — tombol hanya muncul untuk `pending` status.

## 5. Risks & Tradeoffs

- **Backward compat**: Payment records lama tetap bisa diakses — hanya charge baru yang divalidasi
- **Edge case**: Custom API key (non-Midtrans) jika digunakan → tapi gateway_name sudah 'midtrans', jadi safe
